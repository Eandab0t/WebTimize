# Browser validation — WebTimize Compressor 0.3.0

Run date: 2026-11-06

Scope: local-only validation of the actual `webtim` output in headed Chrome. No remote service,
GitHub workflow, package registry or deployment was used.

The goal was not “the Python build exits 0.” It was to prove that the built site still renders,
loads resources, decodes images, executes scripts and responds to user interaction.

## Result

The final run loaded **48 pages** — 8 build variants × 6 routes — with:

| Check | Result |
| --- | --- |
| JavaScript exceptions | 0 |
| HTTP failures (excluding the fixture’s absent `/favicon.ico`) | 0 |
| Failed network requests | 0 |
| Broken/zero-size images | 0 |
| Console errors | 0 |
| Interaction failures | 0 |
| Full test suite after fixes | **139 passed** |
| Strictly validated manifests | 4 variants, all entries match output bytes |
| Deterministic repeat builds | identical trees and manifests |

The fixes found by this work are in `webtim/transforms.py` and `webtim/cli.py`, with regression tests
and `CHANGELOG.md` entries. A later image-compatibility check also fixed EXIF orientation and ICC
profile preservation; its tests are included in the 139 count, but the browser fixture does not
contain an oriented image. An animated-PNG regression is also included; the browser fixture's
animation is a GIF, which the transforms already leave alone. No remote changes were made.

The later terminal-identity change added two CLI presentation tests; the current suite is **141

## Fixture

The fixture is generated by `__development/experiments/make_fixture.py` and contains **38 files / 1,142,345 bytes**.
`__development/experiments/` is gitignored; the curated evidence is in `evidence/`.

Routes:

- `/index.html`
- `/docs/page.html`
- `/docs/deep/page.html`
- `/gallery.html`
- `/defer.html`
- `/about.html`

It deliberately includes:

- six HTML pages in root, nested and deeply nested directories;
- CSS with `@import` chains (`app.css → theme.css → nested/more.css`), root-relative and relative
  `url()` references, a query-string URL and an SVG background;
- a real TrueType font copied from the installed DejaVu test font;
- relative and root-relative images, percent-encoded filenames (`img/my%20photo.png`), query and
  fragment references;
- PNG, JPEG, WebP and AVIF images, multiple JPEG widths, `srcset`, a `<picture>` fallback and an
  existing `.webp` collision;
- an animated GIF and PNG with alpha;
- classic external scripts, async scripts, inline scripts, an inline template-literal script, an
  ES module, a static module import, a dynamic `import()`, and a runtime-built image URL;
- interactive counter, form and `<details>` elements, plus runtime-inserted content;
- a non-UTF-8 JavaScript file, binary data and an absolute `og:image` URL.

The fixture itself initially had two bugs that the browser caught: a runtime image URL was relative
to the nested page, and the runtime slot was absent on nested pages. Those were fixture bugs, not
`webtim` bugs; they were corrected before the final run. They are listed under “Failed experiments.”

## Browser comparison

The audit script opened a fresh page for every variant and route, waited for
`document.readyState === "complete"` and application boot, then collected:

- `document.title` and normalized body text;
- every image’s `src`, `currentSrc`, `complete`, `naturalWidth` and `naturalHeight`;
- computed CSS background URLs, script attributes, fonts and resource timing;
- console messages, `Runtime.exceptionThrown`, HTTP response status and failed requests;
- screenshots at 1440 × 900.

### Functional results

Across all 48 page loads:

- body text was stable at the original 292 normalized characters on the home page;
- 11 home-page images loaded in every variant, including the runtime-built image;
- `window.APP_BOOTED`, module ready, dynamic-import ready, nested-template script and font load were
  true in every applicable route;
- nested routes loaded their relative/root-relative CSS, images and scripts;
- the counter, form submission and `<details>` interaction worked in every variant;
- no console exception, failed request or broken image occurred.

The `/defer.html` route confirmed script order explicitly:

| Variant | Scripts | `defer` attributes | `DEFER_ORDER` |
| --- | --- | --- | --- |
| original/default/hash/webp/avif/avif-hash | two external classic | no | ordered |
| defer/full | two external classic | yes, both | ordered |

`/docs/page.html` kept its external script undeferred because that page contains inline code; the
defer transform intentionally skips such pages. `/gallery.html` and `/docs/deep/page.html` were
deferred in the defer/full builds, and their app code still ran.

### Image behavior

The browser selected the expected representation:

- WebP builds: `logo`, `hero`, `my photo` and `transparent` used `.webp`; the existing
  `picture.webp`/`picture.avif` sources were left in place; the animated GIF stayed GIF; the
  runtime image stayed PNG.
- AVIF builds: converted images used `<picture><source type="image/avif">` and the browser’s
  `currentSrc` was `.avif`; the original `<img src>` remained as fallback. `srcset`/CSS/runtime
  images that cannot receive a safe fallback stayed in their original format and were reported.
- Hash/percent/query: `img/my%20photo.<hash>.png`, `logo.<hash>.png?v=2#logo` and
  `srcset` entries all resolved. `currentSrc` preserved the query/fragment where applicable.
- Absolute `og:image` references did not produce duplicate files; the relative image remained
  reachable.

## Hashing and manifests

The `--hash` build renamed **22** hashable assets and recorded **6** conservative skips:

- `img/external.png` — absolute URL reference.
- `img/runtime-*` — assembled at runtime in `js/app.js`.
- `css/theme.css` and `css/nested/more.css` — referenced by imported CSS.
- `js/lazy.js` and `js/module-util.js` — referenced by another code file.

The reason for every skip was emitted as a warning, included in `hashed_skipped`, and written to the
manifest. No attempt was made to rename an asset whose runtime/absolute/imported URL could not be
rewritten.

Manifest validation checked, for every entry:

- schema version 1 and tool/version;
- sorted by original path and unique originals;
- final file exists;
- SHA-256 matches the actual shipped bytes;
- MIME type is meaningful;
- hashed names match `.<8 hex>.<extension>`;
- unhashed entries have a reason;
- absolute/query/percent/space references still resolve in production output.

All four tested manifests passed. A repeat build of the full options produced an identical output
tree and byte-identical manifest; the tree digest was
`755d24900cf80d4241dcb30cf47cb6408c9092890d9a7dd26b617e7616823b94`. The input tree digest was
unchanged by the builds.

## Performance measurements

These are localhost measurements on one Windows machine. They demonstrate relative behavior, not a
production CDN benchmark.

### Build time

| Build | 5-run wall median | Internal median | Output bytes | 38/37 files |
| --- | ---: | ---: | ---: | ---: |
| default | 247.9 ms | 82 ms | 1,140,804 | 38 |
| full (`--hash --webp --inline-small 2048 --defer-scripts`) | 890.4 ms | 712 ms | 1,006,293 | 37 |

The full build is slower because it decodes/encodes images and performs two hashing passes; that is
expected and is not hidden by the report’s output-size win.

### Browser cold/warm

Cold = browser cache cleared before the first load; warm median = four subsequent loads. The first
load’s encoded body bytes are the useful transfer comparison; cached warm loads report zero encoded
bytes for memory-cache hits.

| Variant | Cold load event | Cold encoded body | Cold resources | Warm median load |
| --- | ---: | ---: | ---: | ---: |
| original | 60.2 ms | 1,118,509 | 24 | 28.8 ms |
| default | 51.2 ms | 1,116,729 | 24 | 35.4 ms |
| hash | 55.9 ms | 1,116,759 | 24 | 21.2 ms |
| webp | 54.0 ms | 970,591 | 24 | 31.7 ms |
| avif | 52.8 ms | 1,063,727 | 24 | 38.0 ms |
| full | 51.9 ms | 970,609 | 23 | 22.2 ms |

WebP reduced cold encoded body bytes by about **13.2%**; AVIF by about **4.9%** on this fixture
because several images could not be converted safely. The output-directory AVIF growth is the cost
of preserving fallbacks, not the bytes an AVIF-capable browser fetches. Localhost load timing is
noisy and should not be used to claim a real-world speedup.

## Problems found and fixed

### 1. Runtime filename prefixes were renamed and returned 404

**Reproduction:** the fixture’s `app.js` builds `/img/runtime-` + `1` + `.png`. Before the fix,
`--hash` produced `img/runtime-1.<hash>.png`, `--webp` produced `img/runtime-1.webp`, and the full
build did the same; Chrome requested `/img/runtime-1.png` and received **404**, leaving a broken
runtime image.

**Cause:** `_DYNAMIC_PATH` only recognized a literal directory ending at the concatenation point
(`"img/" + name`). It missed a filename prefix (`"/img/runtime-" + n + ".png"`).

**Fix:** `webtim/transforms.py` now extracts the literal prefix before the dynamic part from both
concatenation and template literals, matches it at a path-segment boundary, and only applies the
extension restriction when the template supplies one. This protects `runtime-*` without blocking
unrelated assets such as `other.png`.

**Regression tests:**

- `test_runtime_filename_prefix_blocks_hashing_without_blocking_siblings`
- `test_runtime_template_filename_prefix_sets_the_extension`
- `test_runtime_filename_prefix_blocks_webp_conversion`

**Re-run:** all hash/webp/full browser routes returned 200; the runtime image loaded at its original
path and `RUNTIME_IMAGE_OK` was true.

### 2. `--defer-scripts` mistook a filename for an attribute

**Reproduction:** `/defer.html` uses `defer-dep.js` and `defer-use.js`. Before the fix, the defer
transform skipped both scripts because its regex looked for `\b(defer|async)\b` anywhere in the tag,
including inside the `src` value. The browser confirmed no `defer` attributes and the report’s
`deferred` count did not include that page.

**Fix:** attribute detection now requires an actual `defer`/`async` token at an attribute boundary;
module detection requires an actual `type=module` token. This does not change behavior for genuine
already-deferred/async/module scripts.

**Regression test:** `test_defer_does_not_mistake_a_filename_for_an_attribute`.

**Re-run:** both `/defer.html` scripts are deferred in the defer/full builds, execute in document
order and set `DEFER_ORDER="ordered"`.

### 3. Negative inline threshold silently acted like zero

**Reproduction:** `--inline-small -1` exited 0 and inlined nothing.

**Fix:** the CLI and the `build()` API reject negative values. The CLI exits 2 with
`--inline-small must be zero or greater`; a regression test verifies it does not create output.
Very large positive values are still accepted because they are explicit user choices; the measured
cost is documented above.

### Fixture-only failures (not product bugs)

- The initial fixture’s runtime URL was relative (`img/runtime-...`), so nested routes requested
  `/docs/img/runtime-1.png`. Changed the fixture to `/img/runtime-...`.
- The initial fixture assumed the runtime slot existed on every page. Added a guard before appending
  and before setting `#dynamic`; nested pages now share the same script without throwing.

## Recommended configurations

### Conservative standard build

```bash
python -m webtim ./site -o ./dist \
  --hash --manifest dist-assets.json --report build-report.json
```

Use this for most static sites when you want minification, gzip/Brotli sidecars, cache-safe hashed
names and machine-readable outputs without changing image formats. Add `--emit-config nginx|caddy`
only after validating the generated snippet in the target server. On this fixture it saves only
0.1% in raw bytes because the font and already-compressed images dominate; its value is correct
sidecars, hashing and diagnostics, not a guaranteed large compression win.

### Measured aggressive build

```bash
python -m webtim ./site -o ./dist \
  --webp --hash --inline-small 2048 --defer-scripts \
  --manifest dist-assets.json --report build-report.json
```

Measured on this fixture: **1,142,345 → 1,006,293 bytes** (11.9% smaller), Brotli wire
1,000,348 bytes; browser cold encoded bytes fell from 1,118,509 to 970,609. The trade-offs are real:

- `--webp` removes the original when the WebP is smaller and does not emit a `<picture>` fallback.
  Use it only where WebP support is acceptable and verify the actual pages.
- `--inline-small 2048` dropped one icon request here but increased output by 437 bytes. Do not
  raise the threshold blindly; 16 KiB/64 KiB grew this site by 8%/43%.
- `--defer-scripts` changes execution timing on pages with no inline classic code. It skips pages
  with inline code, but scripts that assume parser-time execution still need testing.
- The runtime/absolute/imported assets remain unhashed by design; deploy the manifest or keep their
  names valid.

### AVIF variant

```bash
python -m webtim ./site -o ./dist \
  --avif --hash --manifest dist-assets.json --report build-report.json
```

AVIF keeps the original fallback, so the output directory grew 0.9% here, while an AVIF-capable
Chrome fetched about 4.9% fewer encoded body bytes. Use it only if the fallback policy, browser
support and `<picture>` markup are acceptable. `--avif` and `--webp` cannot be combined.

## Remaining limitations

- One synthetic fixture, one OS, one Chrome version and localhost only; no Firefox, Safari, mobile
  browser, CDN, HTTP/2/3, throttling or production cache test.
- No real nginx, Caddy, Python 3.13 or GitHub Actions execution.
- Regex-based reference rewriting still cannot see every runtime-built URL or modern bundler
  construct. The new prefix detector is deliberately conservative and only protects literal
  prefixes it can see.
- AVIF directory growth and WebP’s lack of a `<picture>` fallback are intentional compatibility
  trade-offs, not free savings.
- `--inline-small` is a byte/request trade-off; 2048 is not universally optimal.
- The minifier crash path is exercised by a test double, not by a naturally malformed input.
- No screen-reader or full accessibility audit was performed.
